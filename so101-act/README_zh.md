## 一、一句话讲清楚：我做了个啥？

我在一个**真实机器人手臂**上，跑通了"让机器人自己看、自己抓"的完整流程。

不是仿真、不是看视频——是我亲手把板子刷了系统、把舵机接了线、把手柄弯了几十遍录数据、再训练一个模型，最后**松手让机械臂自己抓东西**。

这叫**具身智能（Embodied Intelligence）**：给 AI 装上一具身体，让它在真实世界里"看见→想清楚→动手"，而且还能从自己动手的失败/成功里学。

> 面试金句：**"别人是读过具身智能，我是把整套栈在真实硬件上跑了一遍。"**

## 二、我的"具身智能全过程"八步走

| ④ | 标定 | 对主臂从臂各跑 `lerobot-calibrate` | 运动学基线 |

## 三、具身智能到底是个啥？（用比喻）

把"普通 AI"和"具身 AI"放一起比：

| 普通 AI | 具身 AI |
|---|---|
| 输入：图片 / 文字 | 输入：**相机画面 + 关节角度（本体感知）** |
| 输出：标签 / 一句话 | 输出：**电机命令（目标角度 / 力矩）** |
| 活在服务器里 | **活在一具真实身体里** |
| 出错没后果 | 出错 = 胳膊撞自己 |

**比喻**：普通 AI 像个只会做阅读理解的学生，看完题写答案；具身 AI 像个真人在厨房——它得看锅、动手翻、尝咸淡，手被烫了下次就知道收着点。智能不是"想出来"的，是"在身体上试出来"的。

SO-101 这条流水线，就是把上面那个"感知→决策→行动"的环，在真实硬件上跑起来了：相机看 → ACT 想 → 舵机动 → 相机再看。

## 四、硬件三件套：大脑、身体、眼睛

### 1) S600（地瓜）板子 = 机器人的"大脑电脑"
- 跑模型、跟舵机说话、收相机画面。
- 架构是 **ARM aarch64**（64位 ARM）——所以必须装 **aarch64 版** Miniconda，x86 的装上去跑不起来（这是真实踩过的坑）。
- 三种接口记住：跟电脑通信用**网线/SSH**；跟舵机通信用 **UART 总线（线）**；跟相机通信用 **USB**。

### 2) SO-101 机械臂 = "身体"
- 开源桌面级，**6 自由度（6-DOF）**，做模仿学习采数据最合适。
- 关节驱动用 **Feetech STS3215 总线舵机**：里面带 12 位磁编码盘、可以菊花链串起来。
- 6 个关节：`shoulder_pan`（肩转）、`shoulder_lift`（肩抬）、`elbow_flex`（肘弯）、`wrist_flex`（腕弯）、`wrist_roll`（腕转，连续旋转要单独标）、`gripper`（夹爪）。

### 3) 电压：主臂 5V / 从臂 12V（必须背下来！）
- **Pro 套件**：主臂 5V（7.4V 舵机），从臂 12V（12V 舵机）。标准套件俩都 5V。
- **为啥**：从臂要出大力抓东西 → 得上 12V 大力舵机；主臂是让你手掰的，要"顺滑跟手" → 用低压舵机。**反接会烧舵机！**
- 口诀：**"干活的（从臂）要劲儿 → 12V；被掰的（主臂）要顺 → 5V。"**

### 4) 主臂 vs 从臂："示范的手" 和 "干活的手"
| | 主臂（你掰） | 从臂（自动动） |
|---|---|---|
| 谁动 | 你的手 | 被命令 |
| 夹爪 | 通常没有 | 有（真抓） |
| 电压 | 5V / 顺滑 | 12V / 大力 |
| 角色 | **传感器**（上报角度） | **执行器**（做动作） |
| 端口 | `leader_port` (如 `/dev/ttyACM1`) | `follower_port` (如 `/dev/ttyACM0`) |

两根臂长一样的（都是 6 关节、一一对应），但**物理上没连在一起**——都插在，由板子在软件里"牵红线"。

### 5) 相机 = 机器人的"眼睛"
- 顶视相机 `topcam`：桌子上方，`/dev/video0`
- 腕部相机 `wristcam`：从臂手腕上，`/dev/video1`
- **关键认知**：相机只是把光变成像素矩阵，**它不会思考**。学习发生在模型里，不发生在相机里。

## 五、接线图（直观看一眼）

![SO-101 x D-Robotics S600 接线拓扑](wiring.svg)

*图1 — 电脑 ↔ S600 走 SSH；S600 ↔ 相机走 USB；S600 ↔ 双臂走 3 线 UART 舵机总线（主臂 5V、从臂 12V）。*

### 接线文字版（实在图挂了能看这个）

```text
                    ┌──────────────────────────────────────────┐
                    │        D-Robotics S600  (大脑)             │
                    └──────┬───────────────┬───────────┬─────────┘
            USB0 (video0) │    USB1 (video1)│           │ UART ×2
                  ┌──────▼──────┐  ┌──────▼──────┐  ┌─▼──────────┐  ┌─▼──────────┐
                  │ 顶视相机    │  │ 腕部相机    │  │ 主臂端口    │  │ 从臂端口    │
                  │ (topcam)   │  │ (wristcam)  │  │ /dev/ttyACM1│  │ /dev/ttyACM0│
                  └─────────────┘  └─────────────┘  └─────┬──────┘  └─────┬──────┘
                                                         │ 3线总线    │ 3线总线
                                                ┌────────▼────────┐   ┌────▼─────────┐
                                                │ 主臂 6×STS3215 │   │ 从臂 6×STS3215 │
                                                │ 供电 5V        │   │ 供电 12V      │
                                                │ (你掰它)       │   │ (它干活)      │
                                                └─────────────────┘   └───────────────┘
```

三种介质，各管一摊：
- **电脑 ↔ S600** = 网络（SSH）
- **S600 ↔ 舵机总线** = UART 线（3 线：红=电源，黑=地，黄/白=数据）
- **S600 ↔ 相机** = USB

### 标准接线顺序（照这个来，别乱）
1. 分清主臂从臂（俩长得一样，自己指定一个当主臂）。
2. 检查每根臂内部舵机的菊花链：6 个 STS3215 串在一条 3 线排线（红/黑/黄）上，ID 预设 1–6。每个接头都晃一晃——松了是最常见的"无声故障"。
3. 把总线插进 S600：主臂→`leader_port`，从臂→`follower_port`。
4. **通电前再三核对电压**：主臂 5V、从臂 12V，接反=烧舵机，这是最危险的一步。
5. 装相机：顶视→USB0，腕部→USB1。
6. 给 S600 上电，电脑连上网准备 SSH。
7. 验证：`lerobot` 能认出俩端口、读出每臂 6 个舵机 ID、俩相机都能出画面 → 接线对了。

## 六、烧录与环境（把"大脑"弄活）

> 这是全流程的 ①+② 步，本质是"给机器人装系统"。

**A. 用 XBurn 烧 S600 固件**
1. 电脑开 XBurn（地瓜的烧录工具）。
2. 选讲师给的 `product.zip`（~7.9GB，里面已经打包好 LeRobot 环境）。
3. 板子连上电脑，进烧录模式，让 XBurn 识别到。
4. 点 Flash，等进度条走完（几分钟，别断电）。
5. 板子自动重启进 RDK OS。
6. 拿 IP：串口 `plink -serial COMx` 看启动日志，或板子上 `ip a` 看 `eth0`/`wlan0`（别看 `docker0` 那个 172.17 的假网卡）。
7. SSH 登进去：`ssh root@<ip>`。

**B. 搭软件环境**
1. `ssh: connection refused` → 板子还在启动，等 22 端口起来。
2. 装 **Miniconda (aarch64 版)**——x86 的装 ARM 上跑不了。
3. `conda create -n lerobot python=3.10` → `conda activate lerobot`。
4. 在预装的 `lerobot-main` 里 `pip install -e .`（营地网络可能封 443，用讲师内网镜像）。
5. 遇到 `externally-managed-environment`？那是 Debian 不让动系统 Python——**永远在 conda 环境里 pip**，别动系统。
6. `python -c "import lerobot"` 啥也不报错 → 环境好了。

## 七、SO-101 原理深潜（五个要点，建议背熟）

### ① 舵机 = "盒子里装了个聪明马达"
STS3215 不是普通马达，一个巴掌大的盒子里塞了四样：
- **直流马达**（通电就转）
- **减速箱**（转慢、力矩放大 → 输出轴转得慢但有力）
- **磁编码盘**（12 位，永远知道输出轴"此刻转了几度"，像在轴上贴了个迷你指南针）
- **控制电路**（读命令、比对当前角度和目标角度、驱马达）

它跑**位置控制模式**：你给它"转到 30°"，内部 PID 一直推马达直到编码盘读到 30°，然后**自己撑住不动**。所以机械臂能自己保持姿势，不用你扶着。

> 比喻：舵机像个"被设定好角度的弹簧锁"，你告诉它角度，它自己锁到那个角度，重力来推它也不动。

### ② 总线通信 = "一根线上挂六个马达"
老式舵机一个马达一根 PWM 线；SO-101 用**总线**：
- 6 个舵机挂在同一根 3 线总线上（红电/黑地/黄数据）。
- 数据是**半双工 UART**——板和舵机轮流在同一条线上说话（像对讲机，不是打电话）。
- 每个舵机有**唯一 ID**（1、2、3…）。命令说"ID3 转到 45°"，只有 3 号动，别的装死。
- 总线波特率约 **1 Mbps**，所以读/写 6 个关节只要几毫秒。

好处：一根线控 6 个（甚至更多）关节，比 6 根 PWM 线省事，还能白嫖**反馈**（角度、温度、电压、负载）。

### ③ 6 自由度运动学 = "角度怎么变成夹爪位置"
手臂是 6 个转动关节串成的链。给定 6 个关节角，用**正运动学**一算，就知道夹爪在三维空间"在哪、朝哪"。
- 5 个臂关节定位置+姿态，1 个夹爪关节开合。
- **6 自由度 = 3 个定位(x,y,z) + 3 个定向(翻滚/俯仰/偏航)**，刚好够把夹爪放到桌上任意位置任意角度——所以桌面操作标配 6 自由度。
- 全是转动关节，运动链简单好仿真（URDF→MuJoCo/PyBullet）、好控制。

### ④ 主从示教 = "示范，不编程"
两根臂物理一样、关节一一对应，但**不锁死**，都插在 S600 上由软件配对。
- **主臂**：你手掰，舵机跑"顺从/断电"模式——不反抗，只**上报**角度。它是传感器。
- **从臂**：舵机跑"大力位置控制"模式。S600 把主臂角度抄过去当从臂目标 → 从臂**镜像**你的手。它是执行器。

这叫**示教（kinesthetic teaching）**：人扳主臂演示，从臂记下配对角度。不用写代码、不用算轨迹——你**示范**它学。

### ⑤ 视觉 + 闭环 = "为啥它变自主了"
- 相机是纯传感器，只出像素。顶视看全局，腕部看近处夹爪（第一人称）。相机**从不思考**，只供货。
- 一旦 ACT 训好，整条系统就是一个高频**闭环**：

```text
感知 ──► 决策 ──► 行动 ──► (世界变了) ──► 再感知 …
相机+编码盘 → ACT模型 → 目标角度 → 舵机动 → 相机再看
```

因为驱动是位置控制（ACT 输出目标关节角，舵机 PID 追），ACT 的"母语"正好是 SO-101 舵机说的"位置控制语"——所以 ACT 天然贴这硬件。

> 一句背：**舵机=聪明角度锁；总线=一根线按ID喊话；6关节=数学定夹爪；主臂示范从臂抄；相机+模型闭环。**

## 八、遥操循环（两臂到底靠啥连？）

答：**都连在 S600 上**，板子按 ~30–50 次/秒 做"读→抄→发"，不是中间有根铁杆。

```text
 读        抄        发
主臂 ──► S600 ──► 从臂
(30–50 Hz)
```

1. **读**：S600 在总线A发 `读 ID:1`，主臂1号舵机回 `120°`，读完 6 个关节 → `[120°,45°,10°,…]`
2. **抄**：直接拿这串角度当从臂 6 关节的目标
3. **发**：S600 在总线B发 `写 ID:1→30°…`，从臂舵机 PID 追到目标锁住

一个循环才几毫秒，所以两根臂"感觉"是同步的。主臂=你掰的传感器，从臂=被命令的执行器。

**标定为啥必须做**：`lerobot-calibrate` 量每个关节的**最小/最大**（防止自撞）、建立"同一姿势=同一数字"（主从遥操才能对上）、设零点。流程：掰到中位→回车→各关节（除腕转）掰到极限→回车。从臂单独标。这是后面一切的**物理基线**。

## 九、模仿学习（IL）= 这整套的"学习范式"

> 这是 ⑥ 步，也是 ACT/DP 能看懂的前提。

**IL vs RL**
- **模仿学习（IL）** = 看专家演示学。没有奖励、没有试错。你告诉机器人"照我这样来"。
- **强化学习（RL）** = 试错+奖励。自己探索、打分、留高分动作。强但样本效率低、机器人里奖励难设计。

两天训练营里 **IL 是唯一现实选择**——下午就能采几十段好演示，RL 要几千次真试。

**行为克隆（BC）= 最简单的 IL**
BC 就是把监督学习搬进机器人：
- 数据集 `D = {(观察, 动作)}`，观察=相机画面+关节状态，动作=专家当时做的。
- 训一个策略 `π(动作|观察)`，让它的动作尽量贴近演示动作（比如算 MSE）。
- 用的时候：看观察→预测动作→执行。

**就这**。ACT 和 Diffusion Policy 都是 BC 方法——只是它们比"一帧预测一个动作"更聪明地建模了 `(观察→动作)`。

**采集→训练→推理 三段循环**
1. **采集（我亲手干的）**：弯主臂，从臂镜像，程序把每时刻的"双相机画面+主臂角+从臂角"都录下来。一段 = 一长串 `(观察,动作)`。我重复了几十条 → 真数据集。
2. **训练**：把数据集喂给策略网络（这里用 ACT），靠降 BC 误差学会 `f(相机+关节)→动作`，产出模型权重。
3. **推理**：不用再掰了。实时观察→模型→动作→从臂执行→再感知。要起**两个脚本**：`3_start_policy_server`（策略服务=大脑，端着模型）+ `4_run_act_client`（客户端=手，读相机/臂、问大脑、写从臂）。俩都起，臂自己转了。

**IL 经典坑：误差累积（compounding error）**
单步 BC 策略会飘：第 t 步偏一点，第 t+1 步就看到专家从没展示过的状态（分布偏移），误差**滚雪球**直到任务崩。ACT 的"动作分块"和 DP 的"滚动时域"就是为掐断这个雪崩。记住这个——它是从"纯 BC"到"ACT/DP"的桥。

## 十、ACT 详解（面试重点）

**ACT（Action Chunking Transformer）**——斯坦福 Aloha 项目（Zhao et al., RSS 2023）的模仿学习算法。核心问题：让机械臂用**很少**的演示，学会**平滑、稳**的操作。

**输入 → 输出**
- 图像进：顶视+腕部相机 → 视觉骨干（ResNet / DinoViT）特征
- 本体感知进：6 个关节角（臂的"自我感觉"）
- 输出：**一整块**未来动作（比如未来 100 步目标角度，50Hz 下约 2 秒；反应快的任务可以用 20–50 的小块）

**三个设计亮点（面试亮点）**
1. **动作分块（Action Chunking）**：一次预测未来一串动作，不是一步一步。避免误差累积，动作连贯不抖。
2. **CVAE 头**：一个视角常有多种合理解法（抓左/抓右）。VAE 把这种"多模态"塞进潜变量 → 动作更自然。训练时编码演示动作，推理时采样潜变量→解码动作。
3. **Transformer 骨干**：自/交叉注意力把"双相机图 + 关节状态"这种异构输入融成全局上下文。

**时间集成（Temporal Ensembling）= 为啥动作丝滑**
执行时 ACT 每个控制周期都重新预测一整块 k 步，所以任意时刻手里攥着好几块**重叠**的块。它不傻执行最新的那块，而是把"当前这步"在所有重叠块里的预测**做平均**（最新的权重最高）。这把块与块之间的接缝抹平了，消除块边界的抖动——机械臂不会"一块结束下一块开始"时卡顿。

**训练机制**：范式=BC；损失=MSE（预测块 vs 演示块）+ KL（让 VAE 潜变量贴近标准正态）；靠反向传播调权重；数据效率远高于 RL（几十段演示就能学个桌面任务）。

**ACT 为啥这么贴 SO-101**
- 输出=目标关节角，正好是从臂位置控制舵机的"母语"（PID 追目标），ACT 说的是"舵机语"。
- 动作分块+时间集成，吃透了 30–50Hz 闭环：预测一块、平均重叠，把抖的单步策略变成真马达上平滑可复现的动作。
- 双相机+本体感知输入，镜像了物理的"感知-决策-行动"环：眼+自我感觉进，动作出。

## 十一、BC vs ACT vs DP 一桌摆平

| | **BC（单步）** | **ACT** | **DP（扩散策略）** |
|---|---|---|---|
| 论文 | 经典 | Zhao et al., RSS 2023 (Aloha) | Chi et al., RSS 2023 / IJRR 2024 |
| 家族 | 行为克隆 | BC + CVAE + Transformer | 条件 DDPM 的 BC |
| 动作形式 | 一步一算 | **动作分块**（k步） | **动作分块**（k步，滚动时域） |
| 多模态 | 平均→中间差 | CVAE 潜变量（好） | 扩散打分（最好） |
| 推理开销 | 1 次前向 | 1 次前向（快） | K 次去噪（~10步，重） |
| 杀手锏 | — | CVAE + 时间集成 | 迭代去噪 + FiLM 条件 |
| 解决误差累积？ | ❌ 它会中招 | ✅ 分块 | ✅ 滚动时域 |
| 最擅长 | 简单单模态 | 平滑双臂装配 | 强多模态、高维动作 |

**一句话记住**：BC 预测单步（吃误差累积的亏）；ACT 加了 CVAE+分块+时间集成（快、顺）；DP 加了迭代扩散去噪（多模态最丰富、最重）。三者本质都是"从演示学 (观察→动作)"，ACT/DP 只是用分块补了 BC 的致命伤。
