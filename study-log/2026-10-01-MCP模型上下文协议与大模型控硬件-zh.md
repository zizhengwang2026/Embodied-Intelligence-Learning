## 0. 一句话总结

> 我自己的理解：**MCP = 给大模型接外设的“USB 标准”**：它规定了“工具怎么描述自己、模型怎么发现工具、怎么调用、结果怎么回传”，让模型能**自主选择并调用工具**去操作真实世界。它不是普通的 API 封装——普通 API 是你（人）决定调哪个，**MCP 是模型自己决定调哪个**。

## 1. 核心知识点（对照 183–186）

### 1.1 183 MCP 模型上下文协议介绍
- **MCP** 是一套开放协议，用来把**工具 / 数据源 / 设备**以统一方式暴露给大模型。
- 三个角色：
  - **MCP Host**：运行大模型的宿主程序（如聊天客户端、你的机器人主控程序）。
  - **MCP Client**：宿主里负责与服务器通讯的组件。
  - **MCP Server**：提供能力的一方（比如“控制机械臂的服务器”“读文件的服务器”）。
- 它提供的三类能力：**Tools（可调用的函数）、Resources（可读的数据）、Prompts（预置提示模板）**。

### 1.2 184 MCP 客户端与服务器的交互流程
典型流程：
1. **连接与发现**：客户端连上服务器，问“你有哪些工具？”→ 服务器返回工具清单（名字 + 说明 + 参数结构）。
2. **模型决策**：把工具清单作为上下文交给大模型，用户说“把红色方块抓起来” → 模型判断该调 `move_arm` 还是 `grasp`。
3. **调用执行**：客户端按模型给出的工具名与参数，向服务器发起调用。
4. **结果回传**：服务器执行后把结果返回给模型，模型再组织成自然语言答复用户。

### 1.3 185 让大模型拥有控制物理世界设备的能力
- 关键转变：**模型的输出从“一段话”变成“一个结构化的工具调用”**（工具名 + 参数）。
- 于是“说”和“做”被打通：**用户一句话 → 模型选工具 → 真实设备动作 → 结果回传**。

### 1.4 186 MCP 服务器控制真实的硬件
- 典型 MCP Server 会把硬件操作包成几个工具，例如：`set_joint_angle`、`open_gripper`、`get_camera_objects`。
- **工程要点**：
  - 工具描述要写得清楚（模型靠这段说明来决定要不要用），**说明写得含糊，模型就不会用**。
  - 参数要做**范围校验**，别让模型输出的值直接下发到硬件。
  - 危险操作要加**确认环节 / 白名单**。

## 2. 原理（先抓这几条）

1. **MCP 的本质是“让模型自主选工具调用”的协议**，不是一个 API 封装库。
2. **工具清单是给模型看的说明书**，说明写得越清楚，调用越准。
3. **模型输出的下游必须有校验和护栏**，尤其是会动的硬件。

## 2.5 补充细节：MCP 是什么 / 三原语

- MCP = Model Context Protocol，给大模型统一接外部工具与数据的开放协议，底层用 JSON-RPC 通信。
- 三方角色：Host/Client（跑模型、发起调用）、MCP Server（暴露能力）、Tools & 资源（被调用方，如硬件/API/文件）。
- 三原语：Tools（让模型「做事」，可调用）、Resources（给模型「读数据」）、Prompts（给模型「提示模板」）。
- 价值：把「每个工具都写一套 SDK 对接」变成「都接同一标准协议」，换模型/换工具基本不用重写对接代码。
- 接硬件：Server 把机械臂/夹爪/相机等封装成 Tool，模型就能「说一句话」驱动真实设备（见下讲 ALOHA 演示）。

## 5. 常见误区 & 容易踩的坑

| # | 误区 | 真相 |
|---|---|---|
| 1 | MCP 就是普通 API 封装 | 本质区别是**模型自主选择**调用哪个工具，而不是人写死调用逻辑 |
| 2 | 工具说明随便写写 | 模型完全靠这段说明判断用途，写糊了就永远不会被调用 |
| 3 | 模型输出直接下发给硬件 | 必须做参数校验 + 危险操作确认，否则一次幻觉就是一次事故 |
| 4 | 本地小模型也能稳定调工具 | 小模型工具选择能力弱，要精简工具数量、加强描述、加护栏 |
| 5 | 以为接上 MCP 就“什么都能做” | 能力边界 = 你暴露了多少工具，工具集决定它的手脚 |

## 6. DEA 交叉链接（轻量，非主线）

- 对软体执行器而言，**MCP 的安全护栏更关键**：模型一旦误调 `set_voltage` 并输出超范围值，轻则薄膜击穿、重则伤人。建议把工具设计成**语义级**而非物理级（如 `bulge_slightly` 而不是 `set_voltage_kv`），让物理边界封在 Server 内部。
- 这是个能写成论文的口子：**面向软体执行器的大模型工具抽象与安全约束设计**——把“高压危险动作”收敛到少数受审计的工具里。
