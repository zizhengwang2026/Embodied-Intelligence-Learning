## 0. 一句话总结

> **准确率 accuracy 会骗人（类别不平衡时全猜多数类也能拿高分）；混淆矩阵告诉你“错在哪、错成啥”；Precision = 报出来的里有多少是真的，Recall = 真的里有多少被报出来了，F1 = 两者的调和平均。** 做检测/抓取任务时，**漏检和误检的代价通常不一样**，得按场景挑指标。

---

## 1. 核心知识点（对照 141–142）

### 1.1 141 混淆矩阵
以二分类为例，四个格子：

|  | 预测为“正” | 预测为“负” |
|---|---|---|
| **实际是“正”** | **TP**（抓对了） | **FN**（漏了） |
| **实际是“负”** | **FP**（误报） | **TN**（正确排除） |

- 混淆矩阵的用处：**一眼看出模型把 3 认成了几、把 8 认成了几**——多分类时它是一张“错题分布图”。

### 1.2 142 查准率 / 查全率 / F1
- **Precision（查准率）= TP / (TP + FP)**：我报出去的结果里，有多少是真的 → 关心**误报**。
- **Recall（查全率）= TP / (TP + FN)**：所有真的里面，我找出了多少 → 关心**漏检**。
- **F1 = 2·P·R / (P + R)**：两者的**调和平均**，一方很低就会被拉下来，适合综合衡量。

**大白话比喻**：
- 抓娃娃机：你按下抓取 10 次，其中 8 次真抓到了 → Precision = 80%。
- 桌上共有 20 个娃娃，你只抓到 8 个 → Recall = 40%。

---

## 2. 原理（先抓这几条）

1. **Accuracy 在类别不平衡时会骗人**（99% 负样本，全猜负也有 99% 准确率）。
2. **P 和 R 是跷跷板**：阈值调低 → 报得多、R 升 P 降；阈值调高 → 反之。
3. **F1 用来综合**，两方都不能太难看。

## 3. 一张图：四个格子与两个指标

```mermaid
flowchart LR
    T[真实为正 的样本] --> TP[TP 被抓对]
    T --> FN[FN 漏了]
    F[真实为负 的样本] --> FP[FP 误报]
    F --> TN[TN 正确排除]
    TP --> P[Precision = TP/(TP+FP)]
    FN --> R[Recall = TP/(TP+FN)]
    P --> F1[F1 = 2PR/(P+R)]
    R --> F1
```

## 5. 常见误区 & 容易踩的坑

| # | 误区 | 真相 |
|---|---|---|
| 1 | 只看 accuracy | 类别不平衡时严重失真 |
| 2 | 分不清 P 和 R | P 看“报出去的准不准”，R 看“该找的找全没” |
| 3 | 想同时把 P、R 都拉满 | 二者是跷跷板，用 F1 或按业务取舍 |
| 4 | 用算术平均代替 F1 | F1 是**调和**平均，能惩罚“一边极低” |
| 5 | 混淆矩阵只看对角线 | 非对角线才是改进方向（错在哪类） |

---

## 6. DEA 交叉链接（轻量，非主线）

- 软体抓取的评估尤其要看 **Recall（漏检）**：柔性物体轮廓模糊、易变形，检测框容易漏掉目标——漏了就直接抓空。
- 反过来，若你的软体系统靠检测触发高压驱动，**FP（误报）代价很高**（空放一次高压、还可能误夹），此时要偏 **Precision**。软体场景下这两个指标的取舍比刚性臂更敏感。
